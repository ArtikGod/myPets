# Swagger API Документация для AutoRent

## Обзор

Для приложения AutoRent была создана полная Swagger документация API, которая предоставляет интерактивный интерфейс для изучения и тестирования всех endpoints.

## Доступ к документации

После запуска сервера, Swagger UI доступен по адресу:

```
http://localhost:3200/api-docs
```

## Структура API

### 1. Health Check

-   **GET /health** - Проверка состояния сервера
    -   Не требует авторизации
    -   Возвращает статус работы сервера

### 2. Users (Пользователи)

-   **POST /users** - Создать нового пользователя
-   **POST /users/licens** - Добавить водительское удостоверение
-   **GET /users/{id}** - Получить информацию о пользователе
-   **PUT /users/{id}** - Обновить информацию о пользователе
-   **DELETE /users/{id}** - Удалить пользователя

### 3. Vehicles (Автомобили)

-   **POST /vehicle** - Создать новый автомобиль
-   **GET /vehicle** - Получить список автомобилей с фильтрацией и сортировкой
-   **GET /vehicle/{vehicleId}** - Получить информацию об автомобиле
-   **PUT /vehicle/{vehicleId}** - Обновить информацию об автомобиле
-   **DELETE /vehicle/{vehicleId}** - Удалить автомобиль

### 4. Reservations (Бронирования)

-   **POST /reservations** - Создать новое бронирование
-   **GET /reservations/** - Получить историю бронирований пользователя
-   **GET /reservations/{vehicleId}** - Проверить доступность автомобиля
-   **PUT /reservations/{reservationsId}** - Обновить бронирование
-   **PUT /reservations/cancel/{reservationsId}** - Отменить бронирование
-   **GET /reservations/statistic/completed** - Статистика завершенных бронирований
-   **GET /reservations/statistic/users** - Статистика пользователей

## Авторизация

Большинство endpoints требуют авторизации через заголовок `authorization`, который должен содержать MongoDB ObjectId пользователя (24 символа).

### Как использовать авторизацию в Swagger UI:

1. Нажмите кнопку **"Authorize"** в правом верхнем углу
2. Введите MongoDB ObjectId пользователя (например: `507f1f77bcf86cd799439011`)
3. Нажмите **"Authorize"**
4. Теперь все запросы будут автоматически включать заголовок авторизации

## Особенности фильтрации автомобилей

Endpoint `GET /vehicle` поддерживает следующие параметры фильтрации:

-   **sort_by** - Поле для сортировки (make, model, year, price)
-   **order** - Порядок сортировки (asc, desc)
-   **minPrice/maxPrice** - Диапазон цен
-   **minYear/maxYear** - Диапазон годов выпуска

**Важно:** Параметры `sort_by` и `order` должны использоваться вместе или не использоваться вообще.

## Валидация данных

### Пользователи

-   **username** - максимум 50 символов
-   **email** - должен быть валидным email
-   **numberLicens** - точно 10 цифр
-   **dateRelease/dateValidity** - формат ISO 8601 (YYYY-MM-DD)

### Автомобили

-   **year** - от 1900 до текущего года + 1
-   **price** - положительное число

### Бронирования

-   **leaseStart/leaseEnd** - не в прошлом
-   **leaseEnd** - не раньше leaseStart
-   **Максимальный период аренды** - 28 дней

## Коды ответов

-   **200** - Успешный запрос
-   **201** - Ресурс создан
-   **400** - Ошибка валидации
-   **401** - Не авторизован
-   **404** - Ресурс не найден
-   **500** - Внутренняя ошибка сервера

## Тестирование API

Swagger UI позволяет тестировать API прямо из браузера:

1. Выберите нужный endpoint
2. Нажмите **"Try it out"**
3. Заполните необходимые параметры
4. Нажмите **"Execute"**
5. Просмотрите ответ сервера

## Troubleshooting

### Проблема: Swagger UI не загружается

**Симптомы:** При переходе на `/api-docs` отображается ошибка 404 или пустая страница.

**Решения:**

1. Убедитесь, что сервер запущен:
    ```bash
    npm start
    ```
2. Проверьте, что порт 3000 свободен
3. Убедитесь, что файл `src/swagger.ts` существует
4. Проверьте импорт в `src/app.ts`:
    ```typescript
    import { setupSwagger } from "./swagger";
    setupSwagger(app);
    ```

### Проблема: Ошибка "Cannot resolve reference"

**Симптомы:** В Swagger UI отображаются ошибки типа "Cannot resolve reference #/components/schemas/User".

**Решения:**

1. Проверьте, что все схемы определены в `src/swagger.ts`
2. Убедитесь, что имена схем в JSDoc комментариях совпадают с определениями
3. Перезапустите сервер после изменений

### Проблема: Авторизация не работает

**Симптомы:** После ввода токена в "Authorize" запросы возвращают 401 ошибку.

**Решения:**

1. Убедитесь, что токен - это валидный MongoDB ObjectId (24 символа)
2. Проверьте, что пользователь с таким ID существует в базе данных
3. Убедитесь, что заголовок `Authorization` добавлен в CORS настройки

### Проблема: JSDoc комментарии не отображаются

**Симптомы:** Endpoints отображаются без описаний или с неполной информацией.

**Решения:**

1. Проверьте синтаксис JSDoc комментариев (должны начинаться с `/**`)
2. Убедитесь, что путь к файлам в `swagger.ts` корректен:
    ```typescript
    apis: ["./src/**/*.ts"];
    ```
3. Перезапустите сервер после добавления новых комментариев

### Проблема: Ошибки валидации в Swagger UI

**Симптомы:** При тестировании API через Swagger UI возникают неожиданные ошибки валидации.

**Решения:**

1. Проверьте формат данных в примерах
2. Убедитесь, что обязательные поля помечены как `required`
3. Проверьте типы данных (string, number, boolean)
4. Для дат используйте формат ISO 8601: "YYYY-MM-DD"

### Проблема: Медленная загрузка Swagger UI

**Симптомы:** Swagger UI загружается очень долго или зависает.

**Решения:**

1. Уменьшите количество примеров в схемах
2. Проверьте размер JSDoc комментариев
3. Убедитесь, что нет циклических ссылок в схемах
4. Рассмотрите возможность разделения больших схем на меньшие

### Проблема: CORS ошибки при тестировании

**Симптомы:** Ошибки типа "Access to fetch blocked by CORS policy".

**Решения:**

1. Убедитесь, что CORS настроен в `src/app.ts`:
    ```typescript
    res.header("Access-Control-Allow-Headers", "Content-Type, Authorization");
    ```
2. Проверьте, что сервер разработки запущен на том же домене
3. Для продакшена настройте правильные CORS политики

### Проблема: Схемы данных отображаются некорректно

**Симптомы:** В разделе Schemas поля отображаются без типов или описаний.

**Решения:**

1. Проверьте определения схем в `components.schemas`
2. Убедитесь, что все поля имеют указанный тип
3. Добавьте описания и примеры для всех полей
4. Проверьте вложенные объекты и массивы

### Проблема: Endpoints не группируются по тегам

**Симптомы:** Все endpoints отображаются в одной группе или без группировки.

**Решения:**

1. Убедитесь, что в JSDoc комментариях указаны теги:
    ```yaml
    tags: [Users]
    ```
2. Проверьте, что имена тегов одинаковы для связанных endpoints
3. Перезапустите сервер после изменений

### Общие рекомендации по отладке:

1. **Проверьте консоль браузера** - часто там отображаются полезные ошибки
2. **Используйте валидатор OpenAPI** - онлайн инструменты для проверки спецификации
3. **Проверьте логи сервера** - ошибки компиляции TypeScript или синтаксические ошибки
4. **Тестируйте поэтапно** - добавляйте документацию по одному endpoint за раз
