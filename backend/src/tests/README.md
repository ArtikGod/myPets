# Unit Tests для Psychology Bot API

## Описание

Этот каталог содержит unit-тесты для всех основных компонентов API психолог-бота. Тесты покрывают следующие области:

-   **Аутентификация** (`auth.test.ts`) - регистрация, вход, выход, проверка токенов
-   **Задания** (`tasks.test.ts`) - получение заданий, отметка выполнения, история
-   **Прогресс** (`progress.test.ts`) - статистика пользователя, графики, достижения
-   **Пользовательские задания** (`customTasks.test.ts`) - CRUD операции с пользовательскими заданиями
-   **AI сервис** (`ai.test.ts`) - генерация упражнений через OpenAI API
-   **Админ панель** (`admin.test.ts`) - управление пользователями, упражнениями, статистика

## Структура тестов

```
src/tests/
├── auth.test.ts           # Тесты аутентификации
├── tasks.test.ts          # Тесты заданий

└── README.md              # Этот файл
```

## Настройка тестовой среды

### Предварительные требования

1. **PostgreSQL** - должен быть запущен локально или в Docker
2. **Node.js** - версия 18 или выше
3. **npm** - для установки зависимостей

### Установка зависимостей

```bash
cd test/backend
npm install
```

### Настройка базы данных

1. Создайте тестовую базу данных:

```sql
CREATE DATABASE psychology_bot_test;
```

2. Скопируйте тестовые переменные окружения:

```bash
cp .env.test .env
```

3. Обновите `DATABASE_URL` в `.env` если необходимо

### Генерация Prisma клиента

```bash
npm run db:generate
```

## Запуск тестов

### Все тесты

## Конфигурация Jest

Конфигурация Jest находится в файле `jest.config.js`:

-   **Preset**: `ts-jest` для поддержки TypeScript
-   **Test Environment**: `node` для серверных тестов
-   **Setup Files**: `src/tests/setup.ts` для инициализации
-   **Coverage**: настроено для отчетов о покрытии кода
-   **Timeout**: 30 секунд для каждого теста

## Структура тестов

Каждый тестовый файл следует общей структуре:

```typescript
describe("API Module", () => {
    beforeAll(async () => {
        // Настройка перед всеми тестами
    });

    afterAll(async () => {
        // Очистка после всех тестов
    });

    describe("Endpoint Group", () => {
        it("should perform specific action", async () => {
            // Тест конкретного сценария
        });
    });
});
```

## Тестовые данные

Тесты используют:

-   **Временные пользователи** - создаются и удаляются для каждого теста
-   **Тестовые упражнения** - предопределенный набор для проверки функций
-   **Моковые данные** - для внешних сервисов (OpenAI, Telegram)

## Покрытие кода

Цель покрытия кода: **80%+**

Отчет о покрытии генерируется в папке `coverage/` и включает:

-   **Statements** - покрытие операторов
-   **Branches** - покрытие ветвлений
-   **Functions** - покрытие функций
-   **Lines** - покрытие строк кода

## Проблемы и решения

### База данных не найдена

```bash
Error: database "psychology_bot_test" does not exist
```

**Решение**: Создайте тестовую базу данных в PostgreSQL

### Ошибки подключения

```bash
Error: connect ECONNREFUSED 127.0.0.1:5432
```

**Решение**: Убедитесь, что PostgreSQL запущен и доступен

### Проблемы с типами

```bash
Cannot find name 'describe'
```

**Решение**: Убедитесь, что установлены `@types/jest` и `@types/supertest`

### Таймауты тестов

```bash
Timeout - Async callback was not invoked within the 5000ms timeout
```

**Решение**: Увеличьте таймаут в `jest.config.js` или используйте `jest.setTimeout()`

## Лучшие практики

1. **Изоляция тестов** - каждый тест должен быть независимым
2. **Очистка данных** - удаляйте тестовые данные после каждого теста
3. **Описательные имена** - используйте понятные названия для тестов
4. **Группировка** - объединяйте связанные тесты в `describe` блоки
5. **Проверка ошибок** - тестируйте как успешные, так и ошибочные сценарии
