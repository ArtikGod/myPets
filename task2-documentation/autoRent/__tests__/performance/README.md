# Performance Tests для AutoRent API

Этот каталог содержит performance тесты для всех основных endpoints API системы аренды автомобилей, использующие библиотеку `autocannon` для нагрузочного тестирования.

## Структура тестов

### 1. `autocannon.vehicle.test.ts`

Тестирует производительность endpoints для работы с транспортными средствами:

-   `POST /vehicle` - создание транспортного средства
-   `GET /vehicle/:vehicleId` - получение данных транспортного средства
-   `GET /vehicle` - получение списка с сортировкой
-   `PUT /vehicle/:vehicleId` - обновление данных
-   `DELETE /vehicle/:vehicleId` - удаление транспортного средства

### 2. `autocannon.users.test.ts`

Тестирует производительность endpoints для работы с пользователями:

-   `POST /users` - создание пользователя
-   `POST /users/licens` - создание лицензии
-   `GET /users/:id` - получение данных пользователя
-   `PUT /users/:id` - обновление данных пользователя
-   `DELETE /users/:id` - удаление пользователя
-   Стресс-тест множественных создания пользователей

### 3. `autocannon.reservations.test.ts`

Тестирует производительность endpoints для работы с бронированиями:

-   `POST /reservations` - создание бронирования
-   `GET /reservations/:vehicleId` - проверка доступности
-   `GET /reservations/` - история бронирований
-   `GET /reservations/statistic/completed` - статистика завершенных
-   `GET /reservations/statistic/users` - статистика пользователей
-   `PUT /reservations/:reservationsId` - обновление бронирования
-   `PUT /reservations/cancel/:reservationsId` - отмена бронирования
-   Стресс-тест множественных бронирований

### 4. `autocannon.all.test.ts`

Комплексные тесты производительности:

-   Тестирование всех основных endpoints
-   Смешанная нагрузка на разные типы операций
-   Стресс-тест системы под высокой нагрузкой
-   Тест последовательных операций (workflow)

## Запуск тестов

### Отдельные тесты

```bash
# Тест vehicle endpoints
npm run test:performance:vehicle

# Тест users endpoints
npm run test:performance:users

# Тест reservations endpoints
npm run test:performance:reservations

# Комплексный тест всех endpoints
npm run test:performance:all
```

### Все тесты

```bash
# Запуск только комплексного теста (рекомендуется)
npm run test:performance

# Запуск всех тестов последовательно
npm run test:performance:full
```

## Метрики производительности

### Основные показатели:

-   **RPS (Requests Per Second)** - количество запросов в секунду
-   **Latency** - задержка ответа в миллисекундах
-   **Throughput** - пропускная способность в байтах/сек
-   **Errors** - количество ошибок

### Ожидаемые значения:

#### GET операции:

-   RPS: > 80-100
-   Latency: < 500ms

#### POST операции:

-   RPS: > 30-50
-   Latency: < 1500ms

#### PUT/DELETE операции:

-   RPS: > 25-40
-   Latency: < 1800ms

#### Статистические операции:

-   RPS: > 40
-   Latency: < 1200ms

## Конфигурация тестов

### Параметры нагрузки:

-   **Connections**: 5-15 одновременных соединений (обычные тесты)
-   **Duration**: 8-10 секунд (обычные тесты)
-   **Stress test**: до 50 соединений, 15-20 секунд

## Интерпретация результатов

### Хорошие показатели:

-   Стабильный RPS без резких падений
-   Низкая задержка (< 1000ms для большинства операций)
-   Минимальное количество ошибок (< 5% от общего числа запросов)
-   99-й процентиль задержки < 5000ms в стресс-тестах

### Проблемные показатели:

-   RPS ниже ожидаемых значений
-   Высокая задержка (> 2000ms)
-   Большое количество ошибок или таймаутов
-   Нестабильная производительность

## Рекомендации по оптимизации

1. **База данных**:

    - Добавить индексы для часто запрашиваемых полей
    - Оптимизировать запросы с агрегацией
    - Использовать connection pooling

2. **API**:

    - Кэширование часто запрашиваемых данных
    - Пагинация для больших списков
    - Асинхронная обработка тяжелых операций

3. **Инфраструктура**:
    - Масштабирование серверов
    - Load balancing
    - CDN для статических ресурсов

## Мониторинг в production

Рекомендуется регулярно запускать performance тесты:

-   При каждом релизе
-   После изменений в базе данных
-   При изменении инфраструктуры
-   Еженедельно для мониторинга деградации производительности

## Troubleshooting

### Частые проблемы:

1. **Высокая задержка**:

    - Проверить подключение к базе данных
    - Проверить индексы
    - Проверить нагрузку на сервер

2. **Много ошибок**:

    - Проверить валидность тестовых данных
    - Проверить доступность сервисов
    - Проверить лимиты подключений

3. **Низкий RPS**:
    - Увеличить количество соединений
    - Оптимизировать код обработчиков
    - Проверить блокирующие операции
