# Balance Server API

Веб-сервер для управления балансом пользователей с PostgreSQL и кешированием в памяти.

## Технологии

- **NestJS** - Node.js фреймворк
- **TypeScript** - Типизированный JavaScript
- **PostgreSQL** - Реляционная база данных
- **TypeORM** - ORM для работы с базой данных
- **Cache Manager** - Кеширование в памяти
- **Swagger** - Документация API
- **Class Validator** - Валидация данных

## Структура базы данных

### Таблица `users`

- `id` (int, primary key) - Уникальный идентификатор пользователя
- `balance` (decimal) - Текущий баланс пользователя
- `createdAt` (timestamp) - Дата создания записи
- `updatedAt` (timestamp) - Дата последнего обновления

### Таблица `payment_history`

- `id` (int, primary key) - Уникальный идентификатор операции
- `userId` (int, foreign key) - ID пользователя
- `action` (enum: 'debit'|'credit') - Тип операции (списание/пополнение)
- `amount` (decimal) - Сумма операции
- `description` (varchar) - Описание операции
- `ts` (timestamp) - Временная метка операции

## Установка и запуск

### Предварительные требования

1. **Node.js** (версия 18 или выше)
2. **PostgreSQL** (версия 12 или выше)

### Установка зависимостей

```bash
npm install
```

### Настройка окружения

**ВАЖНО**: Все переменные окружения для базы данных являются обязательными для запуска приложения.

Скопируйте `.env.template` в `.env` и настройте переменные:

```bash
cp .env.template .env
```

Затем отредактируйте файл `.env`:

```env
# Database Configuration (ОБЯЗАТЕЛЬНЫЕ)
DB_HOST=localhost
DB_PORT=5432
DB_USERNAME=postgres
DB_PASSWORD=your_secure_password
DB_NAME=balance_db

# Application Configuration
NODE_ENV=development
PORT=3000
```

#### Безопасность конфигурации

- Приложение **НЕ содержит** дефолтных значений для подключения к базе данных
- Все параметры подключения к БД должны быть явно указаны в переменных окружения
- Это обеспечивает безопасность и предотвращает случайное подключение к неправильной базе данных
- В production окружении обязательно используйте безопасные пароли и настройки
- Никогда не коммитьте файл `.env` с реальными паролями в репозиторий

### Настройка базы данных

**Вариант 1: Автоматическая синхронизация (рекомендуется для разработки)**

Приложение автоматически создаст таблицы при первом запуске благодаря TypeORM.

**Вариант 2: Ручная настройка (опционально)**

1. Создайте базу данных и выполните SQL скрипт:

```bash
psql -U postgres -f init-db.sql
```

Этот скрипт создаст:

- База данных `balance_db`
- Таблицы `users` и `payment_history`
- Тестовый пользователь с ID=1 и балансом 1000
- Необходимые индексы

### Запуск приложения

**Локальный запуск:**

```bash
# Режим разработки
npm run start:dev

# Продакшн режим
npm run build
npm run start:prod
```

**Запуск с Docker:**


Приложение будет доступно по адресу: `http://localhost:3000`

Swagger документация: `http://localhost:3000/api`

## API Endpoints

### 1. Списание баланса

**POST** `/balance/debit`

Списывает указанную сумму с баланса пользователя.

**Тело запроса:**

```json
{
  "userId": 1,
  "amount": 100.5,
  "description": "Покупка товара"
}
```

**Ответ:**

```json
{
  "success": true,
  "userId": 1,
  "previousBalance": 1000.5,
  "newBalance": 900.0,
  "debitedAmount": 100.5,
  "transactionId": 123,
  "timestamp": "2024-01-01T12:00:00.000Z"
}
```

### 2. Получение баланса пользователя

**GET** `/balance/user/:userId`

**Ответ:**

```json
{
  "userId": 1,
  "balance": 900.0
}
```

### 3. История операций пользователя

**GET** `/balance/history/:userId?limit=50`

**Ответ:**

```json
[
  {
    "id": 123,
    "userId": 1,
    "action": "debit",
    "amount": 100.5,
    "description": "Покупка товара",
    "ts": "2024-01-01T12:00:00.000Z"
  }
]
```

### 4. Создание пользователя (для тестирования)

**POST** `/balance/user`

**Тело запроса:**

```json
{
  "initialBalance": 1000.0
}
```

### 5. Проверка состояния приложения

**GET** `/health`

**Ответ:**

```json
{
  "status": "OK",
  "timestamp": "2024-01-01T12:00:00.000Z"
}
```

## Особенности реализации

### Транзакционность

Все операции с балансом выполняются в транзакциях для обеспечения консистентности данных.

### Пересчет баланса

После каждой операции баланс пересчитывается по истории операций, что обеспечивает точность данных.

### Кеширование

Балансы пользователей кешируются в памяти на 5 минут для повышения производительности.

### Валидация

Все входящие данные проходят валидацию с помощью class-validator.

### Блокировки

При списании средств используется пессимистическая блокировка записи пользователя.

## Тестирование

### Пример использования с curl

1. **Создание пользователя:**

```bash
curl -X POST http://localhost:3000/balance/user \
  -H "Content-Type: application/json" \
  -d '{"initialBalance": 1000}'
```

2. **Списание средств:**

```bash
curl -X POST http://localhost:3000/balance/debit \
  -H "Content-Type: application/json" \
  -d '{
    "userId": 1,
    "amount": 100.50,
    "description": "Покупка товара за $100"
  }'
```

3. **Проверка баланса:**

```bash
curl http://localhost:3000/balance/user/1
```

4. **История операций:**

```bash
curl http://localhost:3000/balance/history/1?limit=10
```

## Обработка ошибок

- **400 Bad Request** - Некорректные данные или недостаточно средств
- **404 Not Found** - Пользователь не найден
- **500 Internal Server Error** - Внутренняя ошибка сервера

Приложение логирует все операции и ошибки. В режиме разработки включено подробное логирование SQL запросов.
